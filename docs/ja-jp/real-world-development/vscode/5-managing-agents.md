GitHub Copilot のエージェントモードでは、Copilot は自律的にコードベースを調べ、変更を提案し、ファイルを編集してコマンドを実行します。VS Code の Copilot Chat では、ツールの呼び出しやファイルの編集をリアルタイムで確認できます。差分をインラインでレビューし、個々の変更を受け入れるか取り消すか選び、追加プロンプトで会話を導いて、エディターを離れずに作業を改善・拡張できます。

この演習では、次のことを行います。

- アクセシビリティエージェントの作業をリアルタイムで監視します。
- 提案されたファイル編集を確認して受け入れます。
- セッションの途中でエージェントにライトモードのトグルを追加するよう依頼します。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティカスタムエージェントが、高コントラストモードを実装しています。作業中、デザインチームから新たな依頼がありました。既定のテーマが暗すぎると感じるユーザー向けに、ライトモードのトグルも追加したいとのことです。新しい会話を始めずに、進行中のセッションを導いて機能を拡張します。

## Copilot の進行状況を監視する

Copilot Chat ビューには、エージェントが行う操作、調べるファイル、実行するコマンド、提案する編集が表示されます。ファイル編集の差分はチャット内に表示され、**Keep** と **Undo** を選べます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントが作業している間、チャットをスクロールしてツールの呼び出しを確認します。ファイルの読み取りや編集、実行を求めるターミナルコマンドが表示されます。
3. エージェントがファイルの編集を提案したら、インラインで表示される差分を確認します。
   - 変更を受け入れるには **Keep** を選択します。
   - 変更を取り消してエージェントに再度作業させるには **Undo** を選択します。
4. チャット上部の **Files changed** を開き、このセッション中にエージェントが変更したファイル全体を確認することもできます。

> [!NOTE]
> ターミナルコマンドの実行などで許可が必要な場合、エージェントは一時停止して **Allow** を表示します。内容を確認し、許可してよいコマンドだけを承認してください。

5. エージェントが高コントラストモードの実装を終えるまで待ちます。最後に、変更内容の概要が表示されます。

## ライトモードを追加するようエージェントを導く

高コントラストモードができたら、同じ会話でライトモードのトグルを追加します。会話を続けることで、エージェントは変更済みのコンポーネント、スタイルの方針、local storage のパターンなど、前の作業のコンテキストを保持します。

1. Copilot Chat の入力欄に次の追加プロンプトを送信します。

   ```plaintext
   Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
   ```

2. エージェントがすでに行った変更を調べ、ライトモードを追加する様子を確認します。
3. 高コントラストモードのときと同じように、新しい編集を1つずつレビューし、各差分で **Keep** または **Undo** を選択します。
4. エージェントが意図と異なる方向に進んだ場合 (たとえば、トグル UI を望まない形でリファクタリングする場合) は、チャット入力欄の横にある **Stop** ボタンで停止し、明確な追加プロンプトを送信します。

> [!TIP]
> 進行中のセッションを導く方が、最初から会話をやり直すより効率的です。追加プロンプトを使って、調整 (「Cascading Style Sheets (CSS) を簡潔にし、セレクターの重複ではなく CSS 変数を使う」)、方針の修正 (「3つ目のトグルは追加せず、既存の設定パネルにライトモードを統合する」)、範囲の拡張 (「両方のトグルにキーボードショートカットも追加する」) を依頼できます。

## 変更されたファイルを確認する

変更をコミットする前に、エージェントが編集した内容を確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧を確認します。Astro コンポーネント、スタイル、関連テストなどが更新されています。
3. 変更されたファイルをいくつか開き、差分を確認します。カスタムエージェントのアクセシビリティ指針に沿って、Accessible Rich Internet Applications (ARIA) 属性、キーボード操作、セマンティックな HyperText Markup Language (HTML)、local storage による設定の保存が行われていることを確認します。
4. 内容に問題がなければ、Source Control パネルから変更をステージしてコミットします。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat のエージェントモードを使って、進行中のセッションを監視し、方向付けしました。各ファイルの編集を確認して受け入れるか取り消し、コンテキストを失わずに追加プロンプトで作業を拡張しました。

このレッスンでは、次のことを行いました。

- エージェントの作業をリアルタイムで監視しました。
- 個々のファイル編集を受け入れたり取り消したりしました。
- 追加プロンプトで進行中のセッションを導きました。

次の[レッスン][next-lesson]では、アクセシビリティの作業をプルリクエストとして公開し、このラボでローカルのカスタムエージェントが行った変更をレビューします。
